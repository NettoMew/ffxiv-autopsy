# 谁是发狂王

把一份 FF Logs 战斗报告拆到阶段粒度，再拿每名玩家的成绩去对同职业、同阶段的官方分布，
算出他在这一段里究竟站在什么位置。

进度期的日志几乎全是团灭，没有通关排名可看，整场 DPS 也没有意义——
一把打到 P3 和一把打到 P6 的数字根本不可比。按阶段拆开之后才有一条公平的横轴。

## 它解决的问题

副本统计页给的是每个职业在每个阶段的完整分位曲线，本程序做的是把报告里的实测值放到那条曲线上：

```
钐镰客   P4: The Eyes   8,751   官方中位 7,832   +11.7%   分位 87.0
召唤师   P4: The Eyes   6,774   官方中位 7,241    -6.4%   分位 16.3
```

## 依赖

- Node.js 23.6 以上。程序直接运行 `.ts`，不需要编译，也没有任何 npm 依赖。
- 系统自带的 `curl`。Windows 10 1803 以上、macOS 与主流 Linux 都有；装在别处可用
  环境变量 `FFLOGS_CURL` 指定完整路径。

## 配置

把 `config.example.json` 复制成 `config.json`，填入 FF Logs 的 v1 API key：

```json
{
  "host": "cn.fflogs.com",
  "apiKey": "你的 32 位 key"
}
```

也可以改用环境变量 `FFLOGS_API_KEY` 与 `FFLOGS_HOST`。`config.json` 不进版本库。

## 使用

```bash
node src/main.ts score https://cn.fflogs.com/reports/gY4MwRdjFCzNhnX3
node src/main.ts score gY4MwRdjFCzNhnX3 --format console,html,markdown,csv
node src/main.ts score gY4MwRdjFCzNhnX3 --phase 3 --aggregate best
node src/main.ts baseline --zone 59 --boss 1076
node src/main.ts cache clear
```

| 选项 | 说明 |
| --- | --- |
| `--metric` | `rdps`（默认）、`adps`、`ndps`、`cdps`、`hps` |
| `--fight` | 只评某一把 |
| `--phase` | 只评某个阶段 |
| `--aggregate` | 同一阶段多次 pull 取 `median`（默认）或 `best` |
| `--window` | 官方统计的取样窗口，`2`、`6`、`12` 周，默认 12 |
| `--format` | `console`、`html`、`markdown`、`csv`，逗号叠加 |
| `--out` | 文件输出目录，默认 `out` |
| `--refresh` | 忽略本地缓存重新抓取 |
| `--no-color` | 关闭颜色 |

## 两个分数

**分位**是主分：实测值落在同职业同阶段官方分布的哪个百分位，配色沿用 FF Logs 的分段，
看惯排行榜的人不必重新建立直觉。官方给出 0/10/25/50/75/90/95/99/100 九个锚点，之间线性插值。

**线性分**是 `100 × (实测 − 最低) ÷ (最高 − 最低)`。它直观，但最低值往往来自某个开场就阵亡的
记录，所以只作参考，不当主分。

玩家总评按各阶段时长加权，一分钟的阶段不会和三分钟的阶段同等权重。

## 三条它不会骗人的地方

**被团灭截断的阶段不计分。** 官方分布取自通关记录，每个阶段都是完整的；拿一个打了 66 秒就团灭的
P5 去和完整的 P5 比，结果只会好看而无意义。这类阶段仍会单独列出，但不参与任何分数。

**官方样本少于 30 条的阶段不计分。** 极少有队伍从第一阶段开始打，首阶段的官方记录常常只有个位数，
拿两三条记录当分布，谁都是满分。这类阶段显示为“样本不足”。

**数值口径与官方逐位一致。** 每秒数值的除数是 `combatTime` 而非窗口长度。用它复算国服龙骑榜首的
通关成绩，得到 7972.33690838507，官方公布值是 7972.3369083851，差在 1e-11 量级。
这条有回归测试守着。

## 请求成本

一份完整报告的冷启动约 **49 次请求**：统计页 21 次（1 次页面加 5 个阶段各 4 个数据集），
v1 接口 28 次（1 次战斗列表加 27 个阶段窗口）。所有响应都落磁盘缓存，重跑同一份报告是零请求。
基准按阶段惰性补齐，同一副本换一份报告通常只需报告那一侧的请求。

程序对两个数据源都做了节流，v1 接口会读取响应头里的配额并在结束时报出剩余量。

## 结构

```
src/
  core/      配置、错误、领域类型、终端原语
  net/       v1 接口客户端、统计页数据源与其纯函数解析、HTTP 传输、磁盘缓存
  domain/    阶段切分、数值换算、基准库与分位插值、评分
  render/    控制台、HTML、Markdown、CSV
```

`net/http.ts` 走系统 curl 而不是 Node 内置的 fetch 或 http2，原因写在该文件的注释里：
站点前置的防护按 TLS 握手指纹判断来路，Node 自带的 OpenSSL 指纹在统计页那条路径上一律被挡。
同一处还有另一个实测结论——请求头名写成小写 `accept` 会被判成机器人，写成 `Accept` 才正常。

## 测试

```bash
node --test src/
```

覆盖阶段切分的三种边界、分位插值、数值口径的精确性，以及统计页解析的全部锚点。
解析器的用例用的是真实数值，页面一旦改版，测试会直接指出是哪一处锚点失效。
